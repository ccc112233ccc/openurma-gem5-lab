# 双节点 READ 曲线（2026-10-21）

图表：`read-bandwidth.png`、`read-message-rate.png`、`read-latency.png`，依次为平均带宽、包率和平均延迟。图中圆点、方块、菱形分别表示实机、gem5、QEMU 的观测点，连线仅辅助阅读；标注给出关键转折与具体数值。实机参考为用户给出的单端口、单 Jetty、CTP READ 数据，原始表见 `../physical-read-bw-20261009.csv` 和 `../physical-read-lat-20261009.csv`。带宽沿用 `urma_perftest` 的平均字段，按项目已有解释标为 MiB/s；包率沿用 MsgRate 字段，单位 Mpps。

两种仿真均使用两个端点、一颗 ns-3-UB 交换芯片、每端一条 400 Gbit/s 链路，端点到交换芯片每段 375 ns、交换处理每次 500 ns；客体均为 64 KiB 页。QEMU 是单核 Cortex-A72、TCG icount、`synchronization=required`；gem5 是 3.2 GHz ArmO3、ROI 同步，从兼容的 64KiB checkpoint 恢复。QEMU CPU/内存路径不是 Kunpeng 950 的性能模型。

本轮在两种仿真上各跑了 2B、128B、1KiB、4KiB、64KiB、1MiB 六点 `read_lat` 和 `read_bw`。延迟每点请求 256 次，实机为 16,384 次；仅比较均值趋势，不比较 p99 等尾部。带宽和包率使用同一次 `read_bw` 结果：QEMU 小包每点 4,096 次，64KiB/1MiB 分别 1,024/256 次；gem5 本轮小包也为 4,096 次，64KiB/1MiB 为 1,024/256 次。实机每点 16,384 次。带宽与包率图中的 gem5 **完整 26 点稳态曲线**来自 `../gem5-macos-64k-read-curve-20261020.csv`，其 2B–8KiB 为 16,384 次，大包操作次数按负载体积缩减；本轮六点复测用于检查其再现性。

128 B 时实机、gem5 稳态曲线、QEMU 的包率分别为 **23.098、21.461、0.477 Mpps**；gem5 为实机的 **92.9%**。到 1 MiB 时三者都约为 **0.046 Mpps**，与大包带宽趋近相符。图中 4 KiB 竖线是观察小包包率平台向大包带宽平台过渡的参考位置，不表示硬件 MTU 或固定阈值。
