# QEMU READ：全部 UB 同步关闭对照（2026-10-21）

图：`qemu-sync-ablation.png`。六个消息大小分别是 2 B、128 B、1 KiB、4 KiB、64 KiB、1 MiB；每点延迟请求 256 次，带宽小包 4096 次、64 KiB 1024 次、1 MiB 256 次。两节点均为单核 Cortex-A72、TCG `icount shift=0`、64 KiB 客体内核；单 Jetty、单端口 400 Gbit/s、两段 375 ns 链路与 500 ns 交换处理。JFS/JFR/JFC 上限为 8192/8192/524288。

三种模式：

1. **同步开启**：QEMU↔UDMA、UDMA↔ns-3-UB 均为 `required`。数据来自 `../../experiments/read-compare-20261021/qemu-scan/`。
2. **全部关闭，1 µs 轮询**：两个边界均为 `off`，保留 `icount`；QEMU 的 UB 主机设备按原功能模式默认值每 1000 ns 检查一次。数据来自 `../../experiments/read-compare-20261021/qemu-all-sync-off-poll1us-scan/`。
3. **全部关闭，1 ms 轮询**：两个边界均为 `off`，保留 `icount`；QEMU 的 UB 主机设备每 1000000 ns 检查一次，与同步运行的轮询参数保持一致，但同步运行不依赖这个定时轮询。数据来自 `../../experiments/read-compare-20261021/qemu-all-sync-off-scan/`。

## 解释范围

关闭同步后，QEMU UB 主机适配器改用虚拟时间定时轮询；其实现见 `../../integrations/qemu/ubsim-ub-host.c` 的 `ubsim_poll`。1 ms 轮询对应约 0.001 Mpps 的小包平台，说明该曲线主要反映轮询间隔。缩短到 1 µs 后，小包平台升至约 0.06 Mpps，但仍低于同步模式的约 0.477 Mpps。

两种无同步运行的 UDMA 和 ns-3-UB 统计均为 `sync_steps=0`，并记录大量异步时间戳跳跃。1 µs 轮询下 ns-3-UB 转发、交付的 346624 个网络片段数量相等，READ 请求与响应数量也相等，因此低带宽不是由这轮的丢包造成。跨进程虚拟时间缺少共同前沿；这些 guest 计时曲线只描述当前 QEMU 实现的异步运行行为，不能作为实机或已校准同步仿真的性能预测。
