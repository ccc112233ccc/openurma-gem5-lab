# READ 网络固定延迟校准（2026-10-15）

## 拆分参数

`modern` 是两端点经一颗 ns-3 UB 交换芯片、单物理 400 Gbit/s 端口的拓扑。`peer_latency_ns` 控制每段端点到交换芯片的传播延迟；`peer_switch_delay` 控制交换芯片一次转发的处理延迟。READ 请求和响应各经过两段链路、一次交换芯片，因此只看 READ 往返延迟时，固定网络部分约为 `4 × peer_latency_ns + 2 × peer_switch_delay`。链路传播延迟在 UDMA/网络边界计时，ns-3 的内部 UB link 设为零，避免重复计时。同步步长和主机到 UDMA 的路径都固定为 100 ns，实验没有改变 CPU、内存、provider、端口数或带宽。

用户给出的实机依据是交换芯片每次转发约 500 ns、两节点单向网络路径约 1.27 µs、128B READ 平均 3.38 µs。校准后每段端点链路为 375 ns，交换芯片仍为 500 ns；单向网络路径为 `375 + 500 + 375 = 1250 ns`。这些数值是利用现有实机信息约束出的模型参数，并非对物理链路单独测量的结果。单凭 READ 往返时间不能唯一分离链路和交换芯片各自的真实延迟。

## 对照实验

所有实验从同一 `shell-ready-modern-ddr5-optimized-lq64-sq64-20261014` checkpoint 恢复，使用优化 UDMA provider、`stride_exclusive` L1D 预取器、ArmO3 LQ64/SQ64、单 Jetty 单端口。`read_lat` 每组请求 1024 次，程序报告 1018 个样本；实机参考为 16384 次，尾部百分位不能直接等量比较。

| 端点链路每段 | 交换每次 | 128B READ 平均 | 相对 3.38 µs 实机 |
| ---: | ---: | ---: | ---: |
| 100 ns | 500 ns | 2.29 µs | -32.2% |
| 100 ns | 750 ns | 2.80 µs | -17.2% |
| 375 ns | 500 ns | 3.43 µs | +1.5% |

单独把交换芯片加 250 ns，READ 往返均值约增加 0.51 µs，符合两个转发经过。单独把两段端点链路各加 275 ns，均值约增加 1.14 µs，接近四个链路经过带来的 1.10 µs。由此选择 375/500 ns，而不是任意增大交换处理时间。

| 包长 | 校准后 READ 平均 | 实机平均 | 误差 |
| ---: | ---: | ---: | ---: |
| 2B | 3.37 µs | 3.38 µs | -0.3% |
| 128B | 3.43 µs | 3.38 µs | +1.5% |
| 1024B | 3.45 µs | 3.54 µs | -2.5% |
| 4096B | 3.65 µs | 3.75 µs | -2.7% |

128B READ 带宽三次为 19.321、18.174、19.319 Mops/s，均值 18.938 Mops/s，为实机 23.098 Mops/s 的 82.0%；其中一次波动至 78.7%。4KiB 带宽为 46,650.62 MB/s，对照实机 45,172.39 MB/s 为 103.3%。固定传播时延调整没有显著改变大包链路线速，单次小包包率仍有波动。

随后从新校准 checkpoint 自动恢复，先跑 128B 预热（11.421 Mops/s，不计入稳态），再扫包长。表中带宽沿用双方 `urma_perftest` 的相同输出字段；这一次 128B 偏低，因此另列三个紧接着的相同参数重复跑次。

| 包长 | 仿真平均带宽 | 实机平均带宽 | 仿真/实机 |
| ---: | ---: | ---: | ---: |
| 2B | 34.38 | 37.92 | 90.7% |
| 32B | 554.41 | 699.88 | 79.2% |
| 128B | 2114.60 | 2819.64 | 75.0% |
| 512B | 9649.93 | 11230.64 | 85.9% |
| 2048B | 36785.42 | 43935.38 | 83.7% |
| 4096B | 46673.60 | 45172.39 | 103.3% |
| 8192B | 47008.72 | 45427.33 | 103.5% |

紧随该 sweep 的三次 128B 重复结果为 19.295、19.280、20.120 Mops/s，均值 19.565 Mops/s，为实机的 84.7%。75.0% 的 128B 单点确实发生过，不能删去；它与紧接着三次稳定值的差距说明小包性能仍存在跑次波动。2–2048B 多数点约落在实机 80–90% 区间，4–8KiB 略高于实机约 3%。当前校准配置下没有重新测 16KiB–10MiB，因此不能把 8KiB 的结论直接外推成全大包曲线验证。

**尚未匹配的尾部：** 校准后 128B 的短样本 p99 为 5.72 µs，实机 16384 次 p99 为 3.52 µs。1018 个样本里少量高延迟点会明显影响 p99；在相同样本数、预热和统计方式的长测完成前，不能声称 p99 已校准。平均延迟和包率的结论不依赖这个尾部判断。

## 工程设置与证据

`modern` 默认端点链路现在为 375 ns、交换转发仍为 500 ns，同步步长和 host/UDMA 链路仍为 100 ns。均可通过已有 CLI 参数和环境变量覆盖。校准后协调 checkpoint 为 `shell-ready-modern-ddr5-optimized-lq64-sq64-link375-switch500-20261015`；使用优化镜像并匹配 CPU 参数时，`start-ready` 应自动选择它。

实际 `start-ready` 已自动选择该 checkpoint，双端同步和计时器校验通过；从它恢复后重新测得 128B 平均 3.42 µs、p99 5.68 µs，与保存前的 3.43/5.72 µs 一致。该恢复验证见 `experiments/gem5-read-lat-checkpoint-link375-switch500-20261015/results.csv`。
