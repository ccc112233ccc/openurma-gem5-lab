# 本机仿真工作台

启动：

```sh
./lab ui
```

在本机浏览器打开 `http://127.0.0.1:8765/`。可通过 `--port 8766` 改端口。服务只允许绑定回环地址，不向局域网开放。结束页面服务不会停止已经启动的仿真；需要在“运行”页明确点击“停止仿真”，或使用 `./lab stop` / `./lab stop-qemu`。

## 页面与数据

- **任务**：展示 gem5 和 QEMU 两个只读的单叶交换机示例；模板的实验配方仍可编辑和运行。新建时选择仿真器和主机数量，当前拓扑类型固定为单叶交换机星型，叶子交换机固定一台。gem5 和 QEMU 均支持 2–8 台主机；QEMU 可逐台设置 CPU、核心数和内存。创建表单会显示 checkpoint 恢复或冷启动方式。新任务保存在 `configs/ui-tasks/`；可以复制已有任务及其实验配方。中文显示名保存在同目录的元数据文件中。
- 新建 gem5 任务默认每台 4 GiB 建模内存，2–8 台保持同一机器配置，改变主机数量不会改写容量。相同机器配置可从一份无节点身份的基础 checkpoint 恢复，各实例在恢复后获得独立身份与 UDMA 状态；旧的 32 GB 双节点任务和性能校准 checkpoint 仍可使用。主机属性面板显示生效的 CPU 模型、频率、核数、缓存、内存类型/通道及客体内核版本，并保留 CPU 配置和内存容量编辑。无匹配 checkpoint 时可冷启动。详见 [基础 checkpoint 设计](node-template-checkpoint.md)。
- 仿真启动前和运行中会检查宿主机内存。若持续跌破保护线，当前仿真自动停止；运行页显示「内存保护已停止」及具体可用内存，记录保存在运行目录的 `memory-guard.log`。
- **编排**：顶部配置拓扑规模，后端自动生成主机、UDMA 设备、EID 与交换端口连接。画板占据编排区整行，只展示生成结果，不能拖动、增删节点或重接线。点击主机、连线、交换芯片后，属性区在画布下方展开，显示对应参数；再次点击或按「收起」关闭。修改主机数量时保留仍存在的节点和连线参数。保存时由 `compile_topology` 完整校验。直连 JSON 和命令行启动能力仍保留，但当前网页创建入口只提供单叶交换机。
- **运行**：编排页显示当前配置是 checkpoint 恢复还是冷启动。`checkpoint=auto` 优先选兼容状态，没有时从内核冷启动；`checkpoint=none` 总是冷启动。页面调用 `./lab topology start 任务.json`，由 Python 解析 JSON 并直接启动 gem5/QEMU、UDMA 和 ns-3 进程。启动日志、运行状态和产物目录异步显示。modern/4GB gem5 新任务默认选用带节点模板功能的 64KiB 客体镜像；QEMU 仍使用自己的启动内核和镜像，支持功能或计时模式。

链路的 `latency_ns` 表示主机到交换芯片的单向传播延迟，在对应主机的 UB-NET 边界计时；交换芯片的 `delay_ns` 在 ns-3-UB 入端口处理，每次转发计入一次。画板把它们分开显示。画板给出的固定网络路径总和不含序列化、排队和主机处理时间。

终端抽屉先读取该任务当前运行目录的串口记录；节点运行时，再通过本机 WebSocket 接到对应 UART。终端输出可搜索、逐处定位和切换宽屏；聚焦输出区后可直接输入字符、方向键、Tab、Enter 和 Ctrl 组合键，也可在下方输入框粘贴整条命令。UART 不是 PTY，因此宽屏只改变显示宽度，不会向客体发送终端尺寸。每台主机同时只允许一个工作台终端连接。离线或任务与当前运行拓扑不一致时，只显示该任务可用的记录；不会把另一任务的串口输出误当作当前任务。

## 性能实验与结果

在「运行与实验」页保存配方，可选 READ/WRITE 带宽和延迟、消息大小、Jetty 数、总操作数、预热与测量重复次数、队列深度和超时。每个用例固定双机、单端口；带宽的 `-n` 按 Jetty 数分摊，避免增加 Jetty 时悄悄增加总操作数。延迟测试目前限制为一个 Jetty。一次配方最多 120 个用例，防止误启动长时间实验。

多主机任务可以查看、保存拓扑并启动仿真；内置性能实验配方目前只支持双机，页面在多主机任务中会禁用实验按钮并说明原因。将主机数改回 2 并保存后，可再次使用原任务已保存的双机配方。

「启动前检查」列出拓扑、恢复或冷启动方式、镜像与可执行文件、宿主内存余量、UART 端口、当前任务、双机网络初始化以及串口会话的状态。gem5 检查直接解析 JSON，不调用旧启动脚本。启动仿真后直接运行配方；若双机网络尚未初始化，实验进程会先执行 `./lab sync`。QEMU 在每轮实验前通过串口执行 `ubsim-net-up`，其结果只用于功能检查，不作计时精度判断。运行实验时先关闭工作台中的主机终端，串口由实验进程独占。

每轮实验保存在 `experiments/ui-workbench/run-*/`：`topology.json`、`recipe.json`、运行 manifest、checkpoint manifest、镜像哈希与来源、每次 UART 原文、gem5 同步围栏日志、`results.csv` 和聚合后的 `summary.json`。预热行保留在 CSV 中，但不计入结果均值。实验失败时仍保留已完成的结果和最后一次 UART 原文。

结果表和图按操作、包长、Jetty 数展示仿真测量的重复均值、最小值、最大值及带宽包率。界面只呈现仿真结果；QEMU 的结果仅用于功能检查，不作为计时精度结论。
